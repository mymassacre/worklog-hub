# Локальный стенд Jira

Стенд для исследования запросов веб-клиента и проверки будущего адаптера Jira.
Используются официальный образ Jira Software 10.3.9 (Java 17) и PostgreSQL 16.
Версия выбрана для исследования; соответствие рабочей Jira пока не установлено.
Это не копия рабочей системы: данные и учётные записи только синтетические.

- Текущий экран: `/secure/SetupLicense!default.jspa`, `Specify your license key`.

Это **статическое исследование**, не перехват успешных запросов веб-клиента.
Инструмент управления браузером остановил работу, потому что не смог уверенно
определить URL окна Windows. Первый шаг мастера выполнен через его штатную
HTTP-форму с CSRF-токеном этой же сессии. Ключ лицензии не оформлялся и условия
лицензирования через аккаунт Atlassian не принимались.

Пока не проверены: получение JSON worklog, пагинация на реальных записях,
аутентификация через PAT, создание/изменение/удаление записей, запросы UI
в работающей задаче и совместимость с рабочей Jira. Экспериментальный адаптер
позже реализован по REST-контракту; основания и ограничения приведены ниже.

## Запуск

Из корня репозитория:

```powershell
docker compose -f tools/jira-lab/compose.yaml up -d
docker compose -f tools/jira-lab/compose.yaml ps
```

Откройте <http://127.0.0.1:18080>. Для завершения мастера может понадобиться
действующая или пробная лицензия Jira Data Center. Получение лицензии через
аккаунт Atlassian выполняет пользователь. Ключи лицензий, PAT, Cookie и пароли
рабочих учётных записей не добавляются в файлы стенда или Git.

В конфигурации указан демонстрационный пароль только локальной БД. PostgreSQL
не публикует порт на хост. Jira доступна только на loopback-порту 18080.
Лимиты: Jira — 3 ГиБ / 2 CPU, PostgreSQL — 512 МиБ / 1 CPU.
Автоматического перезапуска контейнеров нет.

Compose-проект `worklog-hub-jira-lab` использует отдельную сеть и отдельные
именованные тома для Jira и PostgreSQL; перезапуски сохраняют данные стенда.

## Остановка

```powershell
docker compose -f tools/jira-lab/compose.yaml stop
```

Остановка сохраняет контейнеры и данные. Для удаления только контейнеров и сети
этого стенда, с сохранением томов:

```powershell
docker compose -f tools/jira-lab/compose.yaml down
```

## Что исследовать после настройки

1. Создать тестовый проект, задачу и несколько списаний с разными датами работы.
2. Посмотреть в Network, какие запросы выполняет просмотр проектов, задачи и
   вкладки worklog. Сохранить только обезличенные методы, пути, параметры и JSON.
3. Проверить чтение с PAT отдельно от браузерной сессии.
4. Проверить пагинацию, изменение и удаление списаний, доступ обычного пользователя.

Наличие маршрута в JavaScript подтверждает только то, что он используется кодом
данной версии. Его успешное выполнение, пригодность PAT и совместимость с рабочим
сервером проверяются отдельно. Стенд не воспроизводит сторонние плагины, SSO
или правила доступа рабочей Jira.

## Продолжение исследования без лицензии

Для понимания REST-контракта лицензированный запуск не потребовался. В классе
`IssueResource` проверены аннотации GET `{issueIdOrKey}/worklog` и тип ответа
`WorklogWithPaginationBean`. Метод принимает только ID/ключ задачи, без
параметров `startAt` / `maxResults`. В `SearchResource` подтверждены JQL-поиск
и параметры постраничного чтения. Эти контракты сопоставлены с официальной
[документацией Jira 9.12.2](https://docs.atlassian.com/software/jira/docs/api/REST/9.12.2/).

По этому контракту реализован экспериментальный `JiraCollector`, CLI и
локальные тесты с синтетическими ответами. Это не подтверждение успешного
чтения реальной Jira, PAT или API сторонних плагинов. Оригинальный веб-клиент
задачи и его Network-трафик по-прежнему не проверены.
